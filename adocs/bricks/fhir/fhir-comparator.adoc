== FHIR Comparator Bricks

The FHIR Comparator Bricks provide a mechanism to compare FHIR resources and identify differences between them. This is especially useful when comparing transformations, ensuring data integrity, or finding changes of different transformation engines.

Manual comparison is tedious and error-prone, particularly for complex FHIR resources with deeply nested structures. Automated comparison helps reduce this effort and improves consistency.

=== Design and Behavior

The comparator is designed to be extensible so that additional comparison strategies can be introduced when needed.

The brick set currently consists of the following modules:

* `fhir-comparator-api-brick` defines the core interfaces and contracts for comparison operations
* `fhir-comparator-fhirpatch-brick` implements comparison logic based on the FHIR Patch standard and enables detailed, structured comparison of FHIR resources
* `fhir-comparator-jsondiff-brick` implements comparison logic based on JSON Diff and provides a lighter-weight comparison approach for FHIR resources in JSON format

In most cases, the consumer decides beforehand which comparison strategy to use. As long as the selected strategy is accessed only through the shared interface, the implementation can be exchanged later without requiring changes in the consumer code. This makes it easier to compare strategies during testing and experimentation.

The comparison result is represented as a link:https://build.fhir.org/parameters-definitions.html[FHIR Parameters resource] containing the list of differences between the source and target resources. This output format is identical to the FHIR Patch standard implemented by HAPI. An empty `Parameters` resource indicates that the compared resources are identical. If the `Parameters` resource contains entries, differences were detected and can be analyzed by the consumer.

The two implementations, `fhir-comparator-fhirpatch-brick` and `fhir-comparator-jsondiff-brick`, may produce different results for the same source and target resources because they use different algorithms and heuristics to identify differences. However, if both compared resources are identical, both implementations produce an empty `Parameters` resource.

=== Use Cases

The FHIR Comparator Bricks are intended for scenarios such as:

* **Transformation Validation**: A resource is transformed into another representation and the result needs to be checked for correctness
* **Reference Comparison**: A resource is built from scratch and needs to be compared against a reference resource

One real project use case is the validation of a carbon copy generated in the context of link:https://www.bfarm.de/DE/Bundesopiumstelle/T-Register/_node.html[BfArM T-Register]. In parallel, the same input resource can be transformed locally using the same xref:fhir-smaps-transformation-brick[FHIR StructureMaps Transformation Brick] to create an expected carbon copy resource. In a final step, the Comparator Brick is used to compare the carbon copy generated by the E-Rezept Fachdienst with the locally generated carbon copy. This makes it possible to verify that both transformation results are equivalent and to analyze any detected differences.
